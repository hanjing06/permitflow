Implementation rules:

1. **Anchors** union three CSVs (road_reconstruction, road_resurfacing, sidewalk_construction). They share the schema shown in CONTEXT — `LOCATION`, `START_YEAR`, `DURATION/ Construction Timeline` (e.g. `"Q3 2025 - Q4 2025"`), `geometry` is a JSON string of LineString or MultiLineString.
   - Parse `DURATION/ Construction Timeline` into (start_date, end_date) via a small `parse_quarter_range()` helper. Q1→01-01, Q2→04-01, Q3→07-01, Q4→10-01; end is last day of end quarter. If parsing fails fall back to START_YEAR (start = `YYYY-01-01`, end = `YYYY-12-31`).
   - Extract `geom_wkt` from the `geometry` JSON column (json.loads → format as WKT via `LINESTRING (...)` / `MULTILINESTRING ((...))`). Use the midpoint of the first ring as `lon`/`lat`.
2. **Candidates** union two CSVs:
   - `utility_cuts.csv` — `PROPOSED_FROM_DATE`, `PROPOSED_TO_DATE` (already real dates). No geometry column — set `geom_wkt = NULL`, `lon`/`lat` = NaN. `street_label = DISPLAY_DESC`. `work_type = INSTALLATION_TYPE_DESC`.
   - `building_permits.csv` — `APPLICATION_DATE` → start_date (use APPLICATION_DATE as start because ISSUED_DATE is often null in future window). `end_date` = NULL. **Apply the D-07 filter** read from hero-block.json (do NOT hardcode here — load it once). `street_label = STREET_NUM + ' ' + STREET_NAME + ' ' + STREET_TYPE`. `work_type = PERMIT_TYPE`. No geometry → `geom_wkt = NULL`.
3. **Future-window filter (D-20):** after parsing dates, keep only rows where `start_date >= get_today()` AND `start_date <= get_today() + 90d`. Anchors with a quarter range may have start_date in the past but end_date in the future — keep those too (`end_date IS NULL OR end_date >= get_today()` AND `start_date <= WINDOW_END`).
4. **Hero-block clip (best-effort):** for anchors that have geometry, keep rows whose lon/lat falls inside the hero bbox loaded from hero-block.json. For candidates with no geometry, **keep all** in the future window (lat/lon-free rows are handled by Plan 03-02's address-overlap fallback). Tag rows that fell inside the bbox with a boolean column `in_hero_bbox`.
5. **DuckDB:** use `duckdb.connect(":memory:")`, `read_csv_auto(...)`, then `con.register("df", df)` for the post-processed DataFrames so other plans can do `con.sql("SELECT * FROM anchors")` if they prefer SQL.
6. `materialize()` writes both DataFrames to `data/anchors.parquet` and `data/candidates.parquet` using pyarrow (DuckDB → COPY TO PARQUET also fine).

At the bottom add:

```python
if __name__ == "__main__":
```

- Empty quarter range like `"2026 - 2027"` (no Q prefix) → start=2026-01-01, end=2027-12-31.
- Malformed JSON in geometry column → log + skip the row.
- All-NaN start_date column (if a CSV is missing dates entirely) → log warning, return empty DataFrame for that source, don't crash.
- `PERMITFLOW_TODAY` env var → if set, override `get_today()` (lets us test against a fixed window).

```python
from data_prep import load_anchors, load_candidates, connect, materialize

def load_future_window():
    """
    Returns (anchors_df, candidates_df) from the materialized parquets.
    If parquets are missing or stale, regenerate them.
    """
    parquet_anchors = os.path.join(os.path.dirname(__file__), "..", "data", "anchors.parquet")
    parquet_candidates = os.path.join(os.path.dirname(__file__), "..", "data", "candidates.parquet")
    if not (os.path.exists(parquet_anchors) and os.path.exists(parquet_candidates)):
        materialize()
    anchors = pd.read_parquet(parquet_anchors)
    candidates = pd.read_parquet(parquet_candidates)
    return anchors, candidates
```
